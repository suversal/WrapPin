# 1.0.21：开发与候选记录

## Build 70：iOS 18+ 与 iPad 适配候选

最低系统调整为 18.0。iOS 18–26 导入电脑生成的 RPPairing，iOS 27 保留本机配对；旧系统的地图坐标、路线起终点和地址解析使用 placemark／CLGeocoder，快捷指令使用 openAppWhenRun 保持前台执行。同一版本覆盖全部受支持系统，仍只有标准版和隧道版两个包。iOS 18 真机运行尚待验收。

## 1.0.21 Build 69：iOS 26 适配候选

## 两个版本的变化

- 最低系统为 iOS 26.0；iOS 26 首次配对通过电脑生成 RPPairing，iOS 27 保留六位码本机配对。
- 文件导入与主动粘贴共用校验：XML/binary plist、密钥配对和设备身份字段；能识别选错的 Lockdown 文件。
- 无效替换保留原来有效记录；活动会话中禁止更换配对文件。
- 标准版继续使用外部设备隧道；两个版本分别保存配对记录。

详细操作见 [iOS 26 电脑配对说明](iOS26Pairing.zh-CN.md)。哈希、包大小和校验记录见[构建记录](../Releases/iOS26-build69/receipt.json)。

## 2026-11-05 标准版真机反馈

用户先测标准版，设备系统为 iOS 26.5。最初在开始定位时报告 `pairVerification / idevice RemotePairing 103`。电脑 idevice_pair v1.1.0 中的 Remote pairing 显示 Validate → Works；在指引保存并导入同一轮新验证文件后，用户回复“这次好了”。

这记录了首轮成功反馈，不等于所有功能或整个 iOS 26 系列已验收。恢复真实位置、路线、后台、重启后重连、隧道版及其他系统版本仍待分别确认；此前失败是否由于新旧文件混用，尚无充分证据。

## 已知的配对提示限制

本包保留原生引擎现有的错误映射，部分配对校验错误仍统一提示为“已保存的配对已失效”。单凭这条提示不能判定记录真的过期。请按 v1.1.0 的 Create → Validate（Works）→ Save 流程保存并导入同一份记录；仍失败时，在“设置 → 连接检测 → 复制诊断”查看阶段与错误类型。诊断细分改进不在本次 Build 69 提交中。
